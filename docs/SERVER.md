## ۲. چه چیزی روی سرور اجرا می‌شود

| سرویس | نقش |
|---|---|
| `nginx` 1.24 | دربان ورودی، درخواست‌ها را به برنامه می‌دهد |
| `divaj.service` | برنامهٔ جنگو با gunicorn روی `127.0.0.1:8000` |

### مسیرهای مهم
| مسیر | محتوا |
|---|---|
| `/opt/divaj` | ریشهٔ پروژه (همان مخزن گیت) |
| `/opt/divaj/backend` | بک‌اند جنگو |
| `/opt/divaj/backend/venv` | محیط پایتون |
| `/opt/divaj/backend/.env` | تنظیمات و رمزها |
| `/opt/divaj/dist` | فایل‌های ساخته‌شدهٔ فرانت (خروجی `npm run build`) |
| `/etc/systemd/system/divaj.service` | تعریف سرویس |
| `/etc/nginx/sites-enabled/divaj` | تنظیمات وب‌سرور |
| `~/backups/` | بک‌آپ‌های دیتابیس (JSON) |

### تنظیمات فعلی nginx
```nginx
server {
    listen 80;
    server_name 95.38.182.148;
    client_max_body_size 10M;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

> **نکته:** `server_name` روی IP تنظیم است، نه دامنه. تا وقتی دامنه اضافه نشود،
> نمی‌توان سایت دوم را روی همین سرور با آدرس جدا بالا آورد.

## ۴. روال استقرار (deploy)

```bash
ssh -i ~/.ssh/divaj_deploy ubuntu@95.38.182.148
cd /opt/divaj
git pull origin master
cd backend && set -a && source .env && set +a
./venv/bin/python manage.py migrate
cd /opt/divaj && npm run build
cd backend && ./venv/bin/python manage.py collectstatic --noinput
sudo systemctl restart divaj
```

### قاعدهٔ همیشگی پیش از استقرار
1. مهاجرت‌های جدید را برای عملیات مخرب بررسی کن (`RemoveField`، `DeleteModel`، `DROP`)
2. بک‌آپ کامل بگیر: `manage.py dumpdata > ~/backups/divaj-<تاریخ>.json` و یک کپی روی کامپیوتر محلی
3. اگر مهاجرت داده‌ای دارد، اول روی یک کپی از دادهٔ واقعی تمرین کن
4. بعد از اجرا، تعداد رکوردهای هر مدل را با قبل مقایسه کن

## ۶. وضعیت و قدم بعدی

**الان:** سایت روی HTTP ساده است، بدون دامنه و بدون SSL. برای سامانه‌ای که
ورود با رمز دارد، این یک ریسک واقعی است.

**برنامه:** خرید یک دامنه و تقسیم آن:

| آدرس | کاربرد |
|---|---|
| `example.ir` و `www.example.ir` | سایت معرفی شرکت (صفحات ثابت) |
| `erp.example.ir` | سامانهٔ گزارش کار (همین برنامه) |

**رکوردهای DNS لازم:**
```
A    @      95.38.182.148
A    www    95.38.182.148
A    erp    95.38.182.148
```

پس از اتصال دامنه: تنظیم دو بلوک nginx، نصب SSL رایگان روی هر دو، و
افزودن دامنهٔ جدید به `ALLOWED_HOSTS` در فایل `.env`.

**ظرفیت:** سایت معرفی شرکت صفحات ثابت است و nginx مستقیم سرو می‌کند —
نه سرویس جدا لازم دارد نه رم اضافه. با ۶۴ گیگ فضای آزاد جا فراوان است.
